Exam Structure Category, Subcategory, Exam, Subject and Questions

Exams are organized in a hierarchy so students can browse them logically instead of one long flat list:

Category e.g. "SSC JE" ↓ Subcategory e.g. "Civil" ↓ Exam e.g. "SOM Test 1" — belongs to one Category + Subcategory ↓ Questions belong to one Exam

Category and Subcategory are managed together on the Manage Categories page — each category can have any number of subcategories underneath it. Every exam is assigned to one category and (optionally) one subcategory when it's created, which is what determines where it appears when a student browses exams.

Subjects are a separate, parallel concept — not a level inside the exam hierarchy. A subject is a named folder used to organize question images (see Images below). You'll typically create one subject per topic area (e.g. "Civil-SOM") and reference it in a question's Image Path as SubjectName/filename.ext.

Questions always belong to exactly one exam (via the exam you select when adding them) and can optionally reference an image stored under a subject.

Creating an Exam — Step by Step From an empty portal to a live, attemptable exam
  1. Create or select a CategoryOpen Manage Categories. If the right category doesn't exist yet (e.g. "SSC JE"), create it.
  2. Create or select a SubcategoryFrom the same page, open the category's Subcategories and add one if needed (e.g. "Civil").
  3. Create the ExamOpen Manage Exams → Add Exam. Assign the Category/Subcategory, and set the name, date and start time, duration, total questions, positive/negative marks, passing percentage and result mode. The Add and Edit forms have no attempts field: a new exam allows unlimited attempts until you set a limit with Bulk Update → Max Attempts (or adjust one student on Manage Attempts).
  4. Set up a Subject (if the exam uses images)Only needed when questions will include images — create/reuse a subject on Manage Subjects to act as the image folder.
  5. Add QuestionsOpen Manage Questions, select your exam, and add questions using whichever method fits — see Adding Questions.
  6. Configure exam settingsDouble-check duration, marks, attempt limit and result mode on Manage Exams before publishing. Use Preview Exam (the eye icon) to see what a student will see; it records no attempt.
  7. Review the questionsUse the search and type/image filters on Manage Questions to check everything looks right.
  8. Make it availableA normal exam is controlled by its Status (Upcoming / Ongoing / Completed): set it to Ongoing to let students attempt it. A Scheduled Exam has no Status field; it opens and closes by the clock (see Scheduled Exams).
If a finished exam isn't attemptable, check its Status first (normal exams) or its date, start time and Cancelled marker (Scheduled Exams). A student also needs attempts left: a limit of 0 or blank means unlimited.

Bulk Update and Export

Tick exams (or Select all on page) to get the selection bar. Bulk Update changes only the fields you explicitly switch on (Category, Date, Duration, Status, Marks, Max Attempts, Passing Percentage, Result Mode, Instructions), shows a review step, then applies everything in one transaction. A timing field is skipped for a Scheduled Exam whose schedule is locked, and the result tells you which exams were skipped. Export Selected builds an exam package (see Import / Export).

Cancel and delete

Cancel (Scheduled Exams only) stops new attempts and can be undone with Restore. Delete permanently removes the exam together with its questions, attempts, results and responses, and cannot be undone.

Results & Release Instant, delayed and manual result modes, and what a student sees while waiting

Each exam has a Result Mode that decides when a student may see their result, score, grade and answer review.

ModeWhen the student sees the result
InstantImmediately after submitting.
DelayedA set number of minutes after the student finishes (the Delay (minutes) field; the list shows "N min delay"). The wait is counted from that attempt's own finish time.
ManualOnly after you press Release on the exam row. Unrelease hides the results again. The button appears only for manual exams.

Until a result is visible, the student sees a Result Pending page instead of the score. For a delayed result it shows a live countdown to the exact release time (it keeps counting correctly after a refresh) and opens the result by itself when the time arrives; for a manual result it re-checks periodically and says the result has not been released yet. The same rule hides the result everywhere else: Result History, the response page, analytics and AI features never show a score or answer key early.

The exam's Passing Percentage is the cut-off the student's result page compares their score against.

Normal Exam Availability Reusing a Normal Exam after its date/time has passed, without editing the schedule

By default, a Normal Exam's configured date/time is a hard expiry: once that window has passed, students can no longer start it — even if you leave (or set) its Status back to Ongoing — until you edit the date/time. Available After Selected Date/Time is an optional per-exam toggle on Manage Exams (Add Exam and Edit Exam) that removes that expiry, so you can reuse the same exam purely by controlling its Status.

When ENABLED:

  1. Status is the only gateThe exam stays attemptable for as long as its Status is Ongoing — its configured date/time no longer expires it, no matter how long ago that date/time was.
  2. Reusable without editing the scheduleIf the exam has drifted to Upcoming/Completed and you want it Live again, just set its Status back to Ongoing. Students can attempt it immediately — there is no need to change the date, start time, or duration at all.
  3. Attempt count still appliesThis toggle only removes the date/time expiry. Each student's Max Attempts limit is completely unaffected — once a student has used all their allowed attempts, they cannot start another one, regardless of this setting.

When DISABLED (the default): a Normal Exam behaves exactly as it always has — its configured date/time still determines when it expires, on top of its Status.

Status (Upcoming/Ongoing/Completed) is what students see labelled on their dashboard either way — this toggle never changes that label. It only changes whether the date/time can additionally block starting an exam whose Status is Ongoing.
This option applies only to Normal Exams. It has no effect on Scheduled Exams — the toggle isn't shown while Scheduled Exam is turned on, and a Scheduled Exam's lifecycle always follows its strict scheduled time window (preparation window, official start/end, late-start rules, auto-submit) exactly as described in the Scheduled Exams section below, with no expiry-toggle equivalent.

Scheduled Exams Auto-opening exams, preparation windows, deadlines and auto-submit

A Scheduled Exam is the alternative to a Manual Exam's admin-controlled Status: instead of you flipping it to Ongoing/Completed yourself, you set a date, start time and duration once, and the portal computes its status automatically from the clock from then on — including an optional preparation/preload window before it goes live, a completion buffer right after the deadline, and server-side auto-submit enforcement that works even if a student's browser is closed.

Rules to know:

  • The schedule form has the date, start time, duration, preparation window, completion buffer and Allow manual submission. There is no attempts field in it; the attempt limit is set with Bulk Update (or per student on Manage Attempts).
  • A new or moved start time must be in the future; the form rejects a start in the past.
  • The schedule locks only when students have attempts on record and the exam is past Upcoming. An exam nobody attempted can always be rescheduled, even if it is already Ongoing or Completed (this also lets you reschedule a cancelled exam). Name, instructions, marks, result mode and questions stay editable regardless.
  • Switching an exam between Normal and Scheduled is blocked once any attempt exists.

This is enough to get you building one, but the full behaviour — every setting, exactly what locks once it's live, cancel/restore, and what a student experiences minute by minute — is covered in its own dedicated guide, linked below.

Turn on the Scheduled Exam toggle on Manage Exams → Add Exam (or on an existing exam's Edit form) to see the extra fields it adds.

AI Question Generation Generate, review and add questions with AI
  1. Start a generation jobWhat to do: choose a mode (Direct Extraction, Concept Mining or Pure Generation), the exam, difficulty, question counts and marks, then give a PDF or a topic. Where: the AI Command Centre. Work through its pre-generation checklist first. Then: the job runs on the server and a progress window opens.
  2. Watch the progress windowIt shows the real numbers from the server: total, completed, processing, queued and failed batches, the overall percentage, the current status message and the questions collected so far. Each batch has its own row. You can refresh the page and the window comes back. Only one generation per admin can run at a time, and there is no cancel button: a started job cannot be stopped, so check the settings before you start.
  3. If some batches failThe result is Partially completed: the questions that succeeded are kept, each failed batch shows its reason, and Retry Failed Batches re-runs only those without paying again for the ones that worked. If every batch fails, the job is Failed and says why.
  4. Review the generated questionsWhat happens next: once complete, the questions load into the same CSV Editor used for CSV import — each one shown as a card with raw and rendered (LaTeX) views.
  5. Edit anything that needs itFix wording, adjust marks or tolerance, change the LaTeX size, delete a question you don't want, or add a Source / Previous Year Tag — the AI never invents one on its own.
  6. Add to the examClick Save to DB to add the reviewed questions to the selected exam, or Export CSV to keep them as a file instead.
Always review AI-generated questions before saving — check the correct answer and any LaTeX rendering, the same way you would for a manually written question. Your administrator may limit how many generations you can start per 24 hours.

AI Configuration Which AI model powers each feature of the portal

AI Configuration (administrators granted AI configuration) shows where AI is used and lets you choose the model behind each feature. Its tabs are Overview, Features, Model Assignments, Model Catalog, Comparison and Providers & Configuration.

The four ideas

  • Provider — the service that serves a model. Currently Groq and Google Gemini.
  • Model — for example GPT-OSS 120B, the Gemini 2.5 / 3.x Flash family and Gemma 4. Each model lists what it can do (text, vision, PDF, structured output) and its published rate limits.
  • Offering — a provider serving a model, written provider/model.
  • Assignment — which offering a feature uses.

Changing a model

  1. Pick a featureOpen Model Assignments and press Change model on the feature.
  2. Select a compatible modelOnly models that support what the feature needs can be chosen; a model whose provider has no API key configured is shown as unavailable.
  3. Review and saveA review step shows the change and nothing is saved until you confirm. Reset to default returns the feature to the default model from the configuration file. Changing one feature never affects another.

Use the Model Catalog to search and filter every model, open one for its details, and tick up to three to compare side by side. Providers & Configuration shows whether each provider's key is set; key values are never displayed. Reload configuration re-reads the configuration file without a restart.

Adding a provider or a model, editing limits or logos and setting API keys is done in the server's configuration (config/ai_models.json and the server environment), not on this page; API keys are never entered or shown here. Images in Questions Two ways to attach an image to a question — classic manual entry, or the new Image Mapping tool

Step Zero — Upload the Image (needed either way)

Both methods below start from the same place: the image file has to already be uploaded to a Subject before it can be attached to any question.

  1. Create or reuse a SubjectWhere to go: Manage Subjects. A Subject is just a named folder for organizing images — e.g. one per topic area.
  2. Upload the image(s)Where to go: Upload Images. Pick the Subject, then drag in the file(s) — the original filename and extension are kept exactly as uploaded.
Manage Subjects Upload Images

Method 1 — Classic Manual Path Entry

The original way to attach an image: type its storage reference directly into the question's own Image Path field.

  1. Open the questionWhere to go: Manage Questions → select the exam → click the pencil icon on the question, or Add Question for a new one.
  2. Find the Image Path fieldIn the Add/Edit Question form it's labeled Image Path (optional). The same field (labeled just Image Path) also appears in every row of Batch Add Questions, and as the image_path column when importing a CSV.
  3. Type the reference in the exact formatType SubjectName/filename.ext — the Subject name exactly as it appears on Manage Subjects, a forward slash, then the filename exactly as it was uploaded, including its extension. Example: physics/ph-1.png.
  4. Save the questionClick Save Changes (Edit) or Add Question (new). Nothing validates the path at this point — a typo is accepted silently.
  5. Verify what was savedBack on the Manage Questions list, the question's Image column shows a small pill with the exact text you entered — hover it to read the full path. This confirms what's stored, not whether it's correct.
  6. Confirm the image actually appearsOpen Preview Exam (the eye icon next to the exam on Manage Exams) and navigate to the question. If the path was wrong, no image renders there — same as on the real Student Exam page.
Common mistakes with this method:
  • Subject name doesn't exactly match Manage Subjects (wrong case, an extra space, or a rename that happened afterward)
  • Filename doesn't exactly match what was uploaded
  • Missing or wrong file extension (.png vs .jpg)
  • A plain typo anywhere in the path
  • The image was never actually uploaded to that Subject
  • The correct file exists, but under a different Subject than the one typed

This method still has its place — a quick one-off fix, or attaching a single image while already editing a question for another reason, without leaving Manage Questions.

Method 2 — Question Image Mapping Recommended

A dedicated visual tool for attaching images to many questions at once, with no manual typing at all. Where to go: Image Mapping in the sidebar.

Why it's recommended over the classic method:

  • No manual path typing — you pick the image, you don't type its name
  • Built for mapping many questions in one visit, not just one
  • Every image shows a real thumbnail before anything is saved
  • Drag-and-drop, with a click-to-select alternative for touch devices
  • The Subject's image library is searchable
  • Every pending change is listed for review before it's saved
  • One "Save All Mappings" click applies everything together
  • Far less room for a filename or path mistake
  1. Open Image MappingWhere to go: the Image Mapping link in the sidebar.
  2. Select ExamStep 1 — pick the exam whose questions need images from the searchable dropdown.
  3. Select SubjectStep 2 — pick the Subject whose uploaded images you want to use. Each option shows how many images it holds, e.g. "Images: 184".
  4. Select QuestionsStep 3 — search and filter the exam's questions (by text, Question Type, or Image Status — No Image / Image Attached / Missing/Broken Image), then tick the ones that need images. Use Select This Page, Select All Matching, or Clear Selection as needed.
  5. Continue to MappingClick Continue to Mapping to open the workspace — Selected Questions on the left, the Subject Image Library on the right.
  6. Map an imageDrag an image card from the right panel and drop it onto a question card on the left. Nothing is saved yet — the question card immediately shows the image with a Pending Mapping badge.
  7. No drag-and-drop? Click insteadClick a question card to make it the active target (it highlights), then click any image in the library — it maps the same way as dragging.
  8. Replace an existing imageOn a question that already has one, click Replace, then drag or click a different image onto it — the new choice simply overwrites the pending one.
  9. Remove an imageClick Remove on a question's card to mark its image for removal, shown as a Pending Removal badge until you save.
  10. Verify visually before savingEvery mapped or current image shows as a real thumbnail on its question card — click a thumbnail to open a larger preview. Confirm each one is the right image before moving on.
  11. Review Pending ChangesClick Review & Save — a panel lists every pending change as "Q<number> → filename", so everything can be checked at a glance before it's committed.
  12. Save All MappingsClick Save All Mappings. All pending changes are saved together in one operation — never one at a time.
  13. Wait for it to finishThe button shows a brief "Saving…" state and is disabled automatically until the save completes — no need to click it again.
  14. Confirm the success messageA confirmation such as "✓ 3 image mappings saved successfully." appears, and the affected question cards update immediately to show their new saved image — no page reload needed.
  15. Verify the final resultOpen Preview Exam for the exam, or check the real Student Exam page, to confirm each image renders correctly where students will actually see it.

Important Notes

  • Images must be uploaded to a Subject first — Image Mapping only shows what's already there, it doesn't upload anything itself.
  • Uploading and mapping are two separate steps: upload the image(s) on Upload Images, then map them on Image Mapping.
  • Picking the wrong Subject in Step 2 means the image you're looking for simply won't be in the library — double-check it's the Subject the image was actually uploaded to.
  • Image Mapping doesn't replace the bulk upload workflow — it's what you use after uploading, to attach what's already there to specific questions.
  • Always visually check every mapped thumbnail before clicking Save All Mappings.
  • For any question mapped through Image Mapping, you never need to type SubjectName/filename.ext by hand.

Troubleshooting / FAQ

I uploaded an image but can't find it in Image Mapping.
Confirm it was uploaded to the Subject selected in Step 2, not a different one — then re-select the Subject (or search again) to refresh the image library.

The image is showing on the wrong question.
Check the Review panel before clicking Save All Mappings — every pending change is listed as "Q<number> → filename", so a misplaced mapping is easy to catch before it's saved.

Can I replace an image a question already has?
Yes — click Replace (or Choose Different) on that question's card and pick a different image from the library.

Can I map several questions at once?
Yes — select the questions that need images, map each one, review the full list of pending changes, then use Save All Mappings once for all of them.

Do I still need to type the image path myself?
Not when using Image Mapping — manual typing is only part of the classic method above.

What happens if Save All Mappings fails?
Nothing is partially applied — a save either fully succeeds or fully fails, never something in between. An error message explains what went wrong (e.g. an image that could no longer be found), and the pending changes stay exactly as they were so the issue can be fixed and the save retried.

For direct browsing or cleanup of the underlying stored files, use Object Storage.

Object Storage Browse, download and clean up stored files and folders

Object Storage (administrators granted Storage management) shows the files the portal keeps in its storage backend (local disk or an S3-compatible bucket; the badge at the top says which). Nothing here changes how the rest of the portal works; it is the raw view of what was uploaded.

  • Browse and search: click a folder to open it, use the breadcrumb to go back, and search keys inside the current folder. Calculate usage counts objects and bytes under the current folder.
  • Files: preview images, download one file, or tick several and Download Selected as one ZIP. Delete Selected permanently removes the ticked files.
  • On a phone each row stacks its name, size and date with the actions beside it.

Deleting folders

  1. Tick the foldersUse the checkbox on each folder row, then press Delete Folders.
  2. ReviewThe dialog lists every selected folder with its file count and size, and tells you which cannot be deleted and why. This step deletes nothing.
  3. ConfirmTick the acknowledgement and type the phrase shown (for example DELETE 2 FOLDERS). The confirmation is tied to you and to exactly those folders and expires after ten minutes.
  4. Read the resultEach folder is reported as deleted, partly deleted or not deleted. The portal never reports success unless every folder was fully deleted; if something failed (for example the storage provider rate-limited the request) you can run it again for what is left.
Folders that are protected:
  • Folders the portal itself relies on: Category/, Profile/, Group/, ChatBackground/ and the numbered Notes attachment folders.
  • Any folder holding an image that a question still uses. Remove or re-map those images first (Image Mapping).
  • Very large folders (over 5,000 files): delete their sub-folders in smaller steps.
Deleting is permanent and cannot be undone. Deleting a Subject's folder here keeps the Subject itself; deleting the Subject on Manage Subjects removes its folder as well.

Questions: CSV export

From Manage Questions → Export CSV for a selected exam, producing the same column set as import (so an export can always be edited and re-imported). The CSV Editor also has its own Export CSV for whatever set of questions is currently being reviewed there.

Whole exams: export and import packages

On Manage Exams, tick exams and press Export Selected. It builds a .zip (format smartai-exams-export-v2) with a manifest of the exams, their questions, the categories, subcategories and Subjects involved, and every image once. A progress bar shows the export; images that are missing in storage are listed as warnings instead of failing silently.

Import Exams takes such a package. The whole file is validated first (structure, versions, counts, file types, sizes and checksums); a bad package changes nothing. Then each exam is imported in its own transaction, one at a time, so a failure rolls back just that exam and removes the images it created.

ItemHow it is matched on import
Category / SubcategorySame name (a subcategory inside its category) is reused; if the spelling differs only by case, spacing or accents, that one match is reused and reported. Several possible matches fail that exam instead of guessing; no match creates a new one.
Subject (image folder)Matched by name the same way. A new Subject is created only if you also have Subject management. Images are restored into their Subject's folder so Image Mapping can find them.
Older v1 packagesStill accepted, but they do not say which Subject an image belonged to, so those images go into a Subject named Imported (created if missing) and the report carries a warning.

Duplicates: use the dropdown next to Import Exams before importing. Skip exams already imported (default) recognises an exam with the same name and identical questions and leaves it alone; Import again as a copy imports it anyway under a renamed copy. Existing records are never renamed or overwritten. When the import ends, a report lists every exam as imported, skipped or failed, with warnings and the reason for each failure.

SSC JE (Category) ⌢ Civil (Subcategory) ⌣ SOM Test 1 (Exam) ⌣ Surveying Test 1 (Exam) ⌣ PYQs (Exam)

Users & Admin Management Access requests, attempts and analytics

Users & Requests

New account access requests appear here for approval or rejection, with a history of past requests, plus user role management.

Manage Attempts

Search by student, exam and status. Each row is one student on one exam: attempts used, any attempt still running, the exam's limit and what is left. You can reset a student's attempts or add / remove attempts for one student or for several at once. Only attempts that have completed or were added by hand count against the limit; a running attempt is shown separately and is never deleted by these actions.

Users Analytics

Two tabs. Results is a filterable table of every result (filter by user, exam and date range; the exam dropdown shows each exam's category, subcategory and question count and can be searched). Analytics shows portal-wide charts for a chosen period and exam, with PNG export of a chart or the whole dashboard.

From a result, View Result opens the score summary and View Response opens that student's own response page for the chosen attempt: every question, their answer, the correct answer, marks, status, images and (where set) the Source / Previous Year Tag. It is the same page the student sees, including Analysis-style layout, navigation and printing, but without AI Explanation, Discuss with AI or the student discussion thread. The result must belong to the exam in the link, otherwise it is not found.

How a user gets a plan

  • Everyone starts on the default plan, Free. An account with no plan set (every existing account, every new one) is Free automatically; you never have to set Free up. A plan that has expired also falls back to Free.
  • You give a user a higher plan in Users & Requests → Users tab → click their plan badge → Change plan. A user cannot change their own plan.
  • Students see their plan in the sidebar and on their Profile page, together with what it includes and which plan unlocks each locked item.

Plan is not admin

  • A plan only decides which student features a user gets. Elite never makes anyone an admin, and an admin on Free has no paid student features.
  • Admin access is the Current Role in Users & Requests. Admin permissions are a separate list, below, and are never part of a plan.

Changing a plan and special access

  • Change a user’s plan: in Users & Requests, open the Users tab, click the plan chip next to the user, choose a plan and save.
  • Custom Access: a user with a grant or a deny on top of their plan shows a Custom Access chip; click the plan or the chip to open the card. There you can see what was granted or denied and until when, remove it with the ×, or Add access: choose Grant or Deny, the feature (admin permissions are listed as Admin: …), optionally a number of days and a reason. A grant can be temporary. A deny always wins over the plan, over an earlier grant and over the admin role (once the feature is enforced).
  • Every plan and access change is recorded in the audit log. The same actions are available from the Access Control API (PUT /api/v01/admin/access/users/<id>/overrides/<feature>, which can also set limits).
  • A plan can have an expiry; after it the user is back on the default plan automatically.

Access requests

Requests for admin access work as before: approving one sets the user’s role. Requests for a plan or a single feature are not built yet; when they are, approving one will create the same grant described above, with its own expiry.

Sensitive admin actions and payments

A feature can carry a passkey marker for sensitive actions, but passkey verification is not implemented and no feature uses it. Payments and subscriptions are not implemented either: a plan and its expiry are set by an administrator.

Changing what a plan contains

Plans, features and limits live in config/entitlements.json; the file’s guide is config/ENTITLEMENTS.md. Moving a feature to another plan, changing a limit, or adding a plan is an edit to that one file: no code changes.
